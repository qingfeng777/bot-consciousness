## 真实时钟微基准

复现命令：

```sh
python3 -m consciousness.benchmark --trials 100 --rate 20 --output benchmark.json
```

原始机器可读结果见 [g1-benchmark.json](g1-benchmark.json)。环境为 Linux 6.8.0-57 x86_64、12 个逻辑 CPU、Python 3.10.12、SQLite 3.37.2；日志与模拟器回执均使用临时目录中的持久 SQLite，WAL / synchronous FULL。

交替提交普通文本与紧急文本，共 200 条输入、100 次抢占，实际速率 20.000 条/秒，耗时 9.980 秒。普通模拟动作预设 30 秒，每次由紧急输入中断。

| 指标 | 实测 |
| --- | ---: |
| 受理后到 stop 请求 p50 | 1.277 ms |
| 受理后到 stop 请求 p95 | 2.005 ms |
| 受理后到 stop 请求 p99 | 3.966 ms |
| 受理后到 stop 请求最大值 | 4.143 ms |
| 输入入口到 stop 请求 p95（包含受理写盘） | 5.642 ms |
| 最大外部动作并发 | 1 |

本负载下请求延迟 p95 ≤100ms、外部并发 ≤1 的检查通过。源码 SHA256 为 `5d15f6df8d64be8ad6a14820f7adfe765058a3fd2f824c09cbe1df2f28320922`，算法为按文件名排序拼接 `consciousness/*.py` 的文件名及原始内容后计算 SHA256。

这只是该机器该负载的一次短时测量，不含物理停止、模型推理或设备网络耗时。原始报告的 maxrss 是进程内存高水位，不能据此判断稳定内存或泄漏。

## 时间回放验收

```sh
python3 -m consciousness replay examples/preemption.jsonl --timed --duration 1 --stop-delay 0.1
```

普通任务在 t=0 到达，紧急任务在 t=0.2 到达，另一个普通任务在 t=0.3 到达；原任务在停止确认后取消，两个后续任务分别完成，总虚拟时长 2.3 秒，最大并发为 1。重复运行结果哈希一致。停止延迟超过超时时限时，结果保持未知并冻结队列；迟到回执不会自动解除冻结。
