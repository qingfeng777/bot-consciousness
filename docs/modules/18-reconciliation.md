# 反矛盾与信念修订

模块编号 M18。判断新旧信息是否真的冲突，并维护可撤回的信念版本。目标是避免静默覆盖与错误确定性，不要求所有信息马上归一成唯一答案。

## 数据与分类

Claim 包含实体、属性、值、单位、条件、有效时间、来源与模态；ConflictCase 含 claims、conflict_type、evidence_graph、status、verification_plan 和 decision。状态为 detected、awaiting_evidence、resolved、unresolved、reopened。

冲突分类至少区分事实互斥、时间变化、实体误关联、单位差异、角色规范冲突和技能效果冲突。先确定实体与适用条件一致，再比较值；“昨晚在 A、今天在 B”不能仅因地点不同判为矛盾。

## 修订过程

候选规范化 → 查找可能冲突事实 → 排除时间和单位假冲突 → 构建证据边 → 评估来源及独立性 → 如有必要生成复测或询问目标 → 写入决策与新有效区间 → 通知依赖模块失效相关摘要和计划。

同一消息被多个模型转述不是独立证据，置信度不能简单累加。直接观测也可能有设备故障，来源优先级是条件化规则，不是永远信任某类来源。对争议事实，检索返回候选及状态，规划器选择不依赖争议事实的方案或请求核实。

## 难点与实验

R18：开放文本的逻辑矛盾识别和证据可靠性。首版限制到实体属性及明确否定关系，模型只提出可能冲突，不独自裁定。以同义、否定、单位换算、条件不同和时间变化案例测量误冲突与漏冲突。

推翻事实时沿 derived_from 边使派生结论进入待验证，不能只改主表留下旧摘要继续被检索。传播有预算和去重，复杂环路进入人工可检查队列而非无限递归。

## 验收与拆分

验证冲突重开、证据撤回、重复来源、实体拆分及派生失效。每个 resolved 冲突必须有决策依据与旧版本，未解决冲突不得输出成唯一确定事实。

- M18-A：冲突本体、规范化规则、结构事实和开放文本基线。
- M18-B：冲突案件、验证目标、修订事务与依赖失效。
- M18-C：反例、撤证和传播回归；开放文本不可靠时限制为候选提示。
