# 运行时与事件基础设施

模块编号 M01。负责事件契约、时钟、事务和资源生命周期，是各认知模块的基础；不决定关注什么，也不选择动作。

## 输入输出与内部组件

输入为外部信号、遥测及模块产生的领域事件，输出为持久化序号与订阅投递。内部划分 SchemaRegistry、EventJournal、Dispatcher、Clock、ResourceBudget 和 LifecycleManager。所有事件带 robot_id、event_id、trace_id、causation_id、schema_version、source、occurred_at、received_at；因果父事件可以为空，但必须有独立追踪 ID。

每个机器人使用一个调度状态写入者。知觉和模型调用在受限工作池执行，结果通过事件返回。事件日志按机器人分配递增 seq；seq 只表示接收顺序，不代表设备观测时间。UTC 时间用于跨系统记录，单调时钟用于超时，回放使用可注入虚拟时钟。

## 处理流程与一致性

入口校验 schema → 按 event_id 去重 → 在同一事务中保存事件及待投递项 → 返回 accepted(seq) → 异步投递 → 消费者提交 checkpoint。投递采用至少一次语义；消费者用 consumer_id 与 event_id 唯一键保持幂等。禁止宣称跨网络动作恰好执行一次，动作语义由 M14 核实。

事件 schema 保留主版本；可选字段增加兼容旧读取器，字段改义必须升主版本并提供迁移器。未知主版本进入隔离队列，不能默默丢弃。模块重启从 checkpoint 回放，但执行模块只做状态核对，不把历史事件当新动作发送。

## 数据和资源预算

events 主键为 robot_id 与 seq，event_id 全局唯一；inbox 去重记录、outbox 待发记录和 module_checkpoints 独立建表。启动时验证 schema 版本及数据库完整性，再恢复订阅和运行状态。原始媒体不写进事件行，保存对象引用和校验值。

预算按模块限制队列长度、并发、单次耗时和内存占用。紧急事件使用独立预留队列，普通队列满时返回 BACKPRESSURE。事务失败不返回成功；磁盘满时停止接收需持久化的普通动作，保留独立停止能力并报告健康故障。

## 验证与决策

验收用重复事件、乱序回调、事务回滚、进程崩溃和时钟跳变验证：已确认事件不丢失、消费不重复生效、同一 robot_id 状态不被两个写入者同时更新。至少在事务前、事务提交后、投递前、消费提交前四个故障点回放。

首版同进程队列加 SQLite；只有单机容量基准无法满足时才评估独立消息系统。此模块不需要模型算法研究，主要风险是事务边界与恢复语义。

## 开发拆分

- M01-A：事件与错误契约、时钟模型、版本兼容样例；交付契约及反例集。
- M01-B：日志、发件箱、幂等消费和生命周期；交付可恢复的基础设施。
- M01-C：崩溃矩阵、容量基准及恢复手册；交付可复现故障报告。
