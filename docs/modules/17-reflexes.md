# 条件反射与快速规则

模块编号 M17。对有明确触发证据的事件生成低延迟反应候选，减少模型等待。反射不能绕过动作限制和串行调度。

## 数据与组件

ReflexRule 保存 rule_id、version、origin、predicate、time_window、priority_class、action_template、refractory_period、applicable_context 和 evidence_refs。origin 区分预置规则与学习候选，学习候选在发布前不能参与匹配。

组件为 RuleCompiler、WindowMatcher、ConflictArbiter 和 ActivationLedger。触发记录包括输入事件、匹配条件、抑制或生效原因及关联任务 ID。

## 匹配和冲突处理

输入归一事件 → 维护有界窗口 → 计算谓词 → 检查上下文和冷却 → 在同级规则中按明确程度、置信证据和配置优先级裁决 → 向调度提交。谓词使用受限比较、存在性及时间组合，不允许任意脚本。

相同刺激在不应期内只更新激活记录；危险程度升级、规则上下文变化或新的独立实体刺激允许重新触发。多个规则产生互斥动作时不得都执行，保存冲突并使用配置裁决；无裁决则请求规划器处理。

## 难点与实验

R17：重复共现是否足以成为稳定条件反射。用正例、近似反例和分布外场景测试触发精确率、召回率、反应延迟及错误动作代价。与无该反射的系统作对照，避免把已有调度规则的效果误归因于学习。

对紧急反射，不能只靠模型语义相似阈值；优先使用确定传感器事件及经过验证的规则。规则阈值按事件类别验证，不使用一个通用置信度门槛。

## 验收与拆分

测试边界时刻、重复刺激、反向刺激、多个规则互斥及中断中的再次刺激。已抑制规则必须保留原因，规则回滚后不再触发旧版本，全部反应仍可被追踪到调度任务。

- M17-A：受限规则语言、窗口语义和反例集。
- M17-B：编译、窗口匹配、不应期和冲突仲裁。
- M17-C：错误触发代价、规则爆炸负载和学习规则准入实验。
