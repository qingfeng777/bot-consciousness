# 可观测性评估与回放平台

模块编号 M20。提供调试、回放、实验比较和发布证据，贯穿每个模块开发，不在最后阶段才补日志。

## 记录结构

Trace 关联输入、关注组、上下文版本、目标、模型请求、计划、动作和反馈。DecisionRecord 保存理由类别、候选分数、规则版本、证据 ID 和被拒绝原因，不要求记录模型私有思维过程。

RunManifest 保存应用版本、契约版本、配置、数据集版本、随机种子、时钟模式、模型标识及驱动能力。MetricSample 区分系统性能、行为效果与模型成本，避免把正常拒绝任务算成系统失败。

## 回放与实验模式

确定性回放使用已录制观察、模型替身和模拟执行器；真实模型再评估单独运行，以衡量版本漂移。回放默认禁止真实输出，适配器显式标记 simulation，启动时拒绝混入真实驱动。

故障注入按命名位置执行，如数据库提交后、动作发送后、停止确认前，带固定种子及期望不变量。实验比较保存基线及候选差异，报告样本量、分层结果、置信区间或波动范围，不能只展示最好的一次。

## 指标与诊断

系统指标含队列水位、关注切换率、抢占请求延迟、停止确认延迟、外部动作并发数、未知结果数和恢复耗时。认知指标含证据准确率、目标成功率、澄清率、重复行为率和错误知识写入率。成本包括模型调用、token、媒体存储及 CPU 时间。

提供按 trace_id 查看轨迹、按任务查看状态、按冲突查看证据以及按实验查看回归的接口。V0 用命令行和结构化导出，图形界面后置，避免调试平台变成另一个主项目。

## 运行与验收

日志按容量和期限轮转，凭据不写日志，原始媒体默认使用引用。备份需包含数据库和配置版本，索引可重建；恢复演练需在独立目录完成。指标系统不可用时本地关键审计仍应保留，不能让监控阻塞紧急停止。

验收要求从任一结果追到输入和版本、同一回放稳定复现状态轨迹、注入故障产生指定告警、恢复报告不掩盖未知动作。性能基准注明机器规格及负载。

## 开发拆分

- M20-A：指标字典、轨迹格式、回放契约及实验报告模板。
- M20-B：采集、虚拟时钟回放、模型替身和故障注入工具。
- M20-C：长跑、容量、备份恢复与版本比较验收。

研发工作包估算和依赖见 [模块工作包](../work-breakdown.md)，系统验收要求见 [跨模块协议与验证](../system-contracts.md)。
