# 角色与行为模式

模块编号 M12。表示机器人稳定身份、当前交互角色和可调整行为模式，明确哪些内容可以学习、哪些约束不随角色变化。

## 数据与职责

IdentityProfile 保存 robot_id、名称、能力引用和稳定边界；RoleDefinition 保存 role_id、适用场景、责任、偏好及版本；RoleAssignment 保存选择依据与有效期；BehaviorPattern 保存触发条件、表达或任务偏好、适用上下文和证据。

角色不能包含任意可执行脚本，行为模式只引用能力与技能 ID。身份配置、角色指派和学习候选分表存储，外部输入称呼机器人为某角色不自动等于有效授权。

## 选择与学习流程

场景、任务和显式配置共同选出候选角色 → 检查角色冲突 → 按显式配置优先于场景推断的顺序裁决 → 生成 RoleSnapshot → 提供给工作记忆及动机。多角色可以并存，但每项偏好有来源和最终冲突解法。

角色学习使用行为结果提出候选，例如对同一用户偏好的假设。候选需含观察样本、适用范围、反例和有效期；验证前只用于提问或离线比较，不能改变已生效角色。角色版本发布后存档旧版本，进行中的计划继续引用原版本，执行前重新检查硬约束。

## 难点与实验

R12：持久偏好与暂时指令的区分。构造一次性要求、反讽、角色扮演、多人不同偏好及用户明确纠正等案例，测量错误固化率和偏好恢复能力。

行为一致性评价基于固定情境下的选择、语言风格与冲突处理，不能只用模型自评分。角色相似度不作为任务成功的替代指标。

## 异常与验收

角色缺失或冲突无法裁决时回退最小默认角色。来源被撤销时使关联候选失效，生效版本进入复核。验收验证学习文本不能增加未注册能力、角色回滚可追踪、同一上下文版本下输出偏好一致。

## 开发拆分

- M12-A：身份与角色边界、冲突优先级及偏好评估集。
- M12-B：角色版本、快照、模式匹配及候选隔离。
- M12-C：多人偏好、临时指令、纠正和回滚验证。
