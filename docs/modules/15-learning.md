# 学习候选生成与验证

> 实现路线更新（0.5.0）：本模块需要的模型生成统一经云端 API 与版本化提示词，使用 [云端模型方案](../cloud-models.md) 中对应 purpose；本地只保留适配、状态、校验和验证流程。

模块编号 M15。学习对象包括技能、行为模式、角色假设和条件反射；本阶段设计的是带证据的候选学习流程，不承诺在线自主训练通用模型。

## 数据和生命周期

ExperienceEpisode 保存初始状态、目标、观察、计划、动作、结果、失败及环境范围；LearningCandidate 保存类型、内容版本、训练证据、反例、适用条件、评估报告和状态。状态为 proposed、screened、evaluating、validated、published、rejected、retired。

组件包括 ExperienceCollector、CandidateMiner、DatasetBuilder、Evaluator、Registry 和 DriftMonitor。采集时区分动作执行失败与任务定义错误，缺少关键反馈的轨迹标记 incomplete，不当作成功样本。

## 处理流程

按场景归集完整轨迹 → 发现重复模式或目标可复用步骤 → 生成候选及适用条件 → 剔除无来源内容 → 构建训练与独立验证集合 → 回放 → 仿真扰动验证 → 输出发布建议。V2 的发布由配置管理显式启用；先不自动发布在线学习结果。

候选必须与现行策略及简单规则基线比较。样本不足以支撑泛化时限制适用环境，不把同一次任务的十次文本改写算作十个独立样本。训练和验证按场景或采集会话分组隔离。

## 难点与实验

R15：因果归因、负迁移和验证证据不足。对候选实施环境扰动、反例加入及移除关键步骤的消融实验，区分偶然共现与稳定可复用能力。记录成功率区间、失败严重度、环境覆盖与回归差异，不只比较平均奖励。

角色、技能和反射使用不同验收器；角色看偏好固化错误，技能看目标成功，反射看误触发和漏触发。统一候选生命周期，不强行共用一个准确率指标。

## 回滚与验收

发布版本绑定证据与评估报告，退役后新任务不可再引用，运行中任务按停止或完成策略处理。漂移检测先触发复核，不直接在线改写阈值。源证据删除后候选标记需重新验证。

验收必须证明失败轨迹也进入数据集，未验证候选不可生效，回滚恢复旧行为，数据泄漏检查可识别同场景跨集合。

## 开发拆分

- M15-A：经验定义、候选生命周期、独立验证集及各类型验收器。
- M15-B：轨迹采集、候选生成、实验注册和版本发布回滚。
- M15-C：负迁移、反例、样本泄漏和漂移实验；不能泛化的候选保持禁用。

研发工作包估算和依赖见 [模块工作包](../work-breakdown.md)，系统验收要求见 [跨模块协议与验证](../system-contracts.md)。
