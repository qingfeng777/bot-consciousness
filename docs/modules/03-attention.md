# 注意力选择与关注切换

模块编号 M03。将输入流变成单一当前关注组，并产生中断请求。关注切换不等于动作已经中断，物理停止由调度与执行协议确认。

## 数据与职责

输入 SemanticObservation、当前目标摘要和 SelfState；输出 FocusGroup(version, event_ids, score_components, expires_at)、AttentionDecision 及 InterruptRequest。内部组件为 EventGrouper、EmergencyDetector、SalienceScorer、FocusArbiter 和 SuppressionCache。

同一时空范围、实体和意图的观察组成一组，例如同一次呼救的声音与视频。仅在时间接近而实体无证据关联时不得合并。临时分组可修订，但旧 focus_version 对应的规划必须失效。

## 选择算法

先检测确定的停止信号与危险规则，再对普通组计算 S = w1×目标相关性 + w2×点名程度 + w3×变化程度 + w4×信息质量 + w5×等待补偿，所有普通特征归一到 0 至 1。紧急级别不参与加权相抵，先按优先级类比较，再比较组内分数。

普通关注切换要求新分数超过当前分数加切换阈值，且最短保持时间已满足；紧急信号绕过保持时间。持有版本和截止时间的关注租约到期后重新评估，不能永久占用。

未选中的信息保留有限候选窗口，重要摘要可进入记忆；不持续触发规划。抑制缓存以场景、规则和来源为键，重复危险提示合并，危险升级或新实体出现时必须解除抑制。

## 难点与实验

R03：测量“频繁切换”与“漏掉重要输入”的权衡。用点名、背景对话、重复报警和场景突变交错的轨迹，扫描阈值及保持时间。先使用规则与可解释权重，只有明确基线缺陷时引入学习排序。

关键指标为紧急召回、普通任务关注延迟、每分钟无效切换次数、长期饥饿率。不得仅用总准确率掩盖稀少紧急事件的漏报。

## 异常与验收

来源持续刷屏按来源限流；紧急预留通道使用独立配额和重复归并。实体分组不确定时保留独立组。并发选组以版本比较更新保证一个有效关注组；旧模型结果只能保存为历史。

验收需证明紧急事件能打断保持期、普通事件不会因噪声持续切换、同一输入重放不产生不同关注轨迹。规则通道延迟按系统验收基准单独测量。
