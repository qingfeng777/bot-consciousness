# 调度与中断控制

模块编号 M08。独占任务状态与外部动作槽位，负责优先级、抢占、暂停、恢复和饥饿控制。

## 队列与数据

Task 包含 task_id、goal_id、priority_class、deadline、enqueue_seq、plan_revision、generation、checkpoint、preconditions、status 和 budget。分别维护待执行队列、等待依赖队列、暂停队列和计算工作池。外部动作只有一个槽位，计算池可并行但有并发上限。

普通任务先按级别、截止时间、入队序号排序。老化只提升非紧急任务，不能进入 P0；时间片只用于可协作暂停的计算和技能边界。P0 队列有独立容量及重复归并规则，不通过无限内存换取“永不拒绝”。

## 状态转换

| 当前状态 | 事件和条件 | 后继状态 | 原子写入 |
| --- | --- | --- | --- |
| queued | 依赖满足、槽位空闲、前置检查通过 | running | generation、动作意图与任务事件 |
| running | 更高优先级到达或用户取消 | interrupt_requested | 原因、待停止动作 ID |
| interrupt_requested | 停止请求已登记 | waiting_stop | 停止请求 ID 与时限 |
| waiting_stop | 对应动作已停止且代次匹配 | paused 或 cancelled | 检查点及停止证据 |
| waiting_stop | 超时或无法核实状态 | outcome_unknown | 全局动作槽位冻结 |
| paused | 重新验证条件及预算通过 | queued | 新规划版本或恢复位置 |
| running | 有匹配的最终结果 | completed 或 failed | 结果与释放槽位事件 |
| outcome_unknown | 状态核对成功 | completed、failed 或 cancelled | 核对证据；不直接转 running |

停止回执匹配被中断动作的原 generation；与此同时递增的是后续决策代次。不能因为决策已过期就丢弃旧动作的停止证据。中断中再收到中断只更新待运行优先级，不反复取消停止处理协程。

## 竞争与恢复

任务状态采用版本比较更新，避免完成结果与中断请求竞争时写入两个终态。完成先到则无需再停；停止先确认但成功结果晚到时保存事实，按驱动回执序列核实最终结果，不能重复执行补偿。

启动时冻结外部动作，恢复未终结任务并逐个查询执行器。只有状态可解释后才释放槽位。实例重启生成新的 epoch，旧实例不能继续写状态；未来多进程部署必须在驱动端校验 fencing token，仅数据库锁不够。

## 验收

基于状态模型生成操作序列，注入连续中断、完成和停止竞态、旧回执、满载、关机和恢复。对每条轨迹断言：外部普通动作并发最多 1；释放槽位必须有结果或停止证据；终态不可被旧事件逆转；普通任务在无持续高优先级负载时最终获得执行。
