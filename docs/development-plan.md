# 机器人意识系统研发计划

本计划对应 [实现设计](implementation-design.md)，以可验收的行为闭环为交付单位。当前仓库交付设计文档；以下任务均为待开发，不表示已有实现。

## 排期假设

估算以 1 名后端工程师、1 名模型及算法工程师持续投入，测试与机器人接口人员按阶段参与为前提。核心研发量估计 66 至 101 人日；两名工程师考虑串行依赖、评审和约 20% 缓冲后，规划 9 至 13 周。真实硬件另计 14 至 24 人日，约 3 至 5 周，受设备和接口准备情况影响。若由单人执行，核心部分约 16 至 25 周。以上是初始估算，完成 V0 后按实测吞吐重估。

角色简称：后端负责状态与运行时，算法负责模型、记忆和学习，测试负责回放及故障注入，机器人负责硬件驱动。角色表示责任类型，不代表已经安排具体人员。

## 里程碑与交付门槛

| 阶段 | 建议时间窗 | 可演示交付 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| M0 契约确认 | 第 1 周 | 数据字典、接口契约、场景清单 | 调度状态与停止语义达成一致 |
| M1 确定性闭环 V0 | 第 2 至 3 周 | 文本输入到模拟执行反馈，支持紧急中断 | 排序、串行、中断、失败与去重测试通过 |
| M2 认知闭环 V1 | 第 4 至 6 周 | 模型计划、记忆检索、角色、自我和动机 | 证据可追踪，模型错误可降级，冲突不静默覆盖 |
| M3 多模态与学习 V2 | 第 7 至 10 周 | 图像和音频接入、场景、技能候选及仿真评估 | 候选与生效策略隔离，反射不绕过调度 |
| M4 集成与发布 | 第 11 至 13 周内 | 回放、故障恢复、指标与可复现实验包 | 场景集及故障集通过，文档与实际能力一致 |
| M5 硬件接入 V3 | 核心完成后 3 至 5 周 | 设备状态、动作、停止确认和在环验证 | 停止与故障行为满足设备验收标准 |

时间窗允许重叠，9 周路径要求接口稳定且后续工作能提前并行；13 周路径包含完整集成缓冲。固定交付日期应在 M1 后确认。

## 核心研发工作项

| ID | 工作项与交付物 | 责任 | 依赖 | 人日 | 验收条件 |
| --- | --- | --- | --- | --- | --- |
| T01 | 数据契约、状态图、接口示例 | 后端 | 无 | 2–3 | 每种事件含版本、来源及关联标识；明确错误码 |
| T02 | 工程骨架、配置和持续集成 | 后端 | T01 | 1–2 | 干净环境可执行测试，不需要模型密钥 |
| T03 | 文本输入、注意力与分组 | 后端 | T02 | 3–4 | 点名、普通、紧急输入正确排序；只有一个关注组 |
| T04 | 工作记忆与事件存储 | 后端 | T02 | 3–4 | 内存有界，事件持久化，来源可查询 |
| T05 | 调度器与中断协议 | 后端 | T01、T03 | 5–7 | 同级稳定排序，抢占等待停止确认，满载时紧急任务可受理 |
| T06 | 模拟执行器与反馈 | 后端 | T04、T05 | 3–4 | 外部动作并发不超过 1；成功、失败、取消均产生反馈 |
| T07 | V0 场景验收 | 测试 | T03–T06 | 2–3 | C01–C05 可重复通过，形成演示操作说明 |
| T08 | 模型网关、计划与格式校验 | 算法 | T01、T02 | 4–6 | 超时和非法计划降级；旧上下文结果不触发动作 |
| T09 | 长期记忆、证据检索与场景 | 算法 | T04 | 4–6 | 基准查询返回证据；跨时间场景变化不误判为冲突 |
| T10 | 自我状态、动机与情绪 | 后端 | T05、T06 | 4–6 | 低电量有迟滞和去重；过期遥测标记未知；情绪不覆盖紧急级别 |
| T11 | 角色、模式与矛盾处理 | 算法 | T09 | 4–6 | 冲突保留双方证据与待验证状态，角色更新可回滚 |
| T12 | 目标中心、定时事件和空闲预算 | 后端 | T04、T10 | 3–5 | 周期任务去重，目标完成可核验，空闲任务可抢占和关闭 |
| T13 | 图像、音频与视频采样接口 | 算法 | T03、T08 | 5–8 | 输出统一语义事件，保留原始引用；感知失败不制造确定事实 |
| T14 | 技能、反射候选与仿真评估 | 算法 | T06、T09、T11 | 6–9 | 成功与失败轨迹均参与评估；候选发布有版本与回滚 |
| T15 | 联想与记忆整理 | 算法 | T09、T12 | 3–5 | 联想标为假设，受预算约束，不直接触发硬件动作 |
| T16 | 恢复、幂等与回执核对 | 后端 | T04–T06 | 5–8 | 崩溃与回执丢失不造成已确认动作重复执行 |
| T17 | 集成回放、故障注入和性能基准 | 测试 | T07–T16 | 6–10 | 全部场景通过，1000 条混合轨迹满足串行不变量，报告延迟 |
| T18 | 配置手册、演示与版本发布 | 后端 | T17 | 3–5 | 新环境可复现演示，记录模型、配置和数据集版本 |
| 合计 | 核心软件研发量 | 团队 | — | 66–101 | 不含硬件采购、标注和外部接口等待 |

## 场景验收清单

| ID | 场景 | 预期结果 | 阶段 |
| --- | --- | --- | --- |
| C01 | 普通问候与点名同时到达 | 点名优先；同级按约定顺序；反馈不会生成新用户任务 | M1 |
| C02 | 普通动作执行中收到火警 | 请求停止，确认停止后再告警，外部动作不重叠 | M1 |
| C03 | 同一输入重投及队列满载 | 重复不执行两次；满载返回原因；紧急输入保留入口 | M1 |
| C04 | 执行器报错后还有待执行任务 | 失败有记录；独立且前置条件有效的任务可继续 | M1 |
| C05 | 停止确认延迟或丢失 | 等待或进入未知状态；不启动下一普通动作 | M1 |
| C06 | 电量在阈值附近抖动 | 迟滞避免充电任务反复生成，恢复后需求解除 | M2 |
| C07 | 模型返回未知动作、坏格式或超时 | 计划被拒绝或降级，不能直接下发执行器 | M2 |
| C08 | 两条事实冲突及场景随时间变化 | 真冲突等待核实；时间变化保留各自有效范围 | M2 |
| C09 | 无用户输入持续运行 | 定时目标正常推进，空闲预算有界，可被新输入抢占 | M2 |
| C10 | 低置信度图片或语音输入 | 保存置信度与来源，必要时询问，不伪造确定观察 | M3 |
| C11 | 同一技能在不同环境成功与失败 | 候选记录适用条件和失败证据，未验证不生效 | M3 |
| C12 | 联想生成与事实相似的内容 | 保持假设标签，不能污染事实检索和直接驱动动作 | M3 |
| C13 | 发送动作后进程崩溃或回执丢失 | 恢复时核对执行状态，不能盲目重放 | M4 |
| C14 | 多个中断连续到达、旧模型结果迟到 | 停止过程不被重复取消破坏，旧代次结果不触发动作 | M4 |
| C15 | 设备断连后恢复 | 状态未知期间阻止普通动作，核实后再恢复 | M5 |

## 验证方式和完成定义

单元测试覆盖排序、预算、状态转换、schema、冲突规则和动机迟滞。集成测试采用可控制时钟与模拟执行器，主动延迟停止确认、丢弃回执和制造过时模型结果，避免只靠真实时间等待。回放测试固定输入轨迹、模型替身、随机种子及配置版本。

模型评估单独记录计划有效率、证据引用正确率、任务成功率、延迟和调用成本；规则通道性能不与模型响应混算。真实设备测试单独记录停止时延与状态查询能力。

每个任务完成需交付实现、相关测试、接口或操作说明、已知限制；涉及持久化时补充迁移与恢复验证。阶段验收需保留实际报告，不以功能演示成功一次代替故障验证。当前设计提交不宣称通过上述运行验收。

## 风险与范围调整

| 风险 | 处理方式 |
| --- | --- |
| 模型延迟与输出不稳定 | 紧急通道规则化，模型调用有预算与格式检查，必要时降级 |
| 硬件无法即时停止 | 提前验证停止协议；不满足协议则不进入真实机器人阶段 |
| 长期记忆被误信息污染 | 证据与版本保留、假设隔离、冲突复核 |
| 学习行为难以复现 | 候选先离线评估，固定轨迹和配置，版本化发布 |
| 功能范围过大导致核心闭环延期 | 优先保证 M1 和 M2；视频连续处理及自动技能发布后置 |
| 无明确设备或模型接口 | 核心先用适配接口和模拟器推进，在对应阶段开始前确定供应商和设备 |

开工时需要确认目标运行平台、模型接入方式、是否必须离线和预计团队规模；这些影响排期及适配实现，不阻塞 V0 的契约和仿真闭环。真实机器人阶段开始前必须取得驱动协议、停止能力说明、遥测格式与测试环境。
